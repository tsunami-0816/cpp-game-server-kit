## [11-11 step7.5] 重置脚本：DELETE 未重置自增，种子 id 漂移到 3/4

- 命令：`bash scripts/step75_reset.sh`（首版）
- 现象：`DELETE FROM users` 后重放 schema 种子，新行 id 变为 3、4（预期 1、2）；探针/回归断言 `uid=1/2` 会失败。
- 根因：`DELETE` 不清 AUTO_INCREMENT 计数器；应使用 `TRUNCATE TABLE users` 重置自增。
- 关联台账：**Q-018**（P3，verified）。
- 修复：`scripts/step75_reset.sh` 第 4 步改 `TRUNCATE TABLE users` 后重放种子。
- 回归：`evidence/reset/db_after_reset.txt` id=1/2；`login_verify.log` 登录 uid=1/2 通过。

## [11-11 step7.5] 重置脚本：Redis DEL 空键集合报参数错误

- 报错：`ERR wrong number of arguments for 'del' command`（`room:*` 无匹配键时 `redis-cli del` 收到空参数）。
- 根因：未先判断键集合非空就拼接 `DEL` 参数。
- 关联台账：**Q-018**（同上，P3 verified）。
- 修复：先 `keys` 取键集合，非空才执行 `DEL`。
- 回归：二次跑 `redis_cleanup.txt` 显示 session/room 影响键数均为 0，无报错；`redis_after.txt` 为空。

## [11-11 step7/7.5] PowerShell → WSL 内联 bash 引号嵌套被吞（执行方式问题，不计代码缺陷）

- 现象：`wsl -d Ubuntu-22.04 -- bash -lc "mysql ... \"SELECT ...\""` 多层引号导致 `unexpected EOF while looking for matching '`。
- 处置：按既定经验（见 experience: powershell-invoke-wsl-bash-via-script-file）改为把 SQL/流程落盘成 `.sh` / `.py` 脚本再在 WSL 内 `bash`/`python3` 执行，规避引号吞噬。
- 关联：无台账编号（执行方式问题，非产品代码缺陷）；产物脚本 `step7_run.sh`、`step75_reset.sh`、`step7_integration.py`、`step7_observe_members.py`、`step75_verify_login.py`。
