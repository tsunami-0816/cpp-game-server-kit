## 1. 校验范围与方法

本项目无 OpenAPI/HTTP 路由，通用脚本 `api_contract_validator.py`（OpenAPI 对账）不适用；按看板既定口径改为 Protobuf 契约对账，三个方向：

1. **消息名对账**：proto 定义消息 ↔ C++ 服务端 `game::Xxx` 引用 ↔ Python 客户端 `game_pb2.Xxx` 引用（机器脚本扫描）。
2. **字段对账**：逐条消息核对字段名/编号在 proto、C++ 读写、Python 读写三方一致（人工对照源码）。
3. **错误码与传输格式对账**：架构 §5.1/§5.3 契约 ↔ 代码实际落地。

## 2. 传输格式契约（实现版固化）

### 2.1 网关 TCP（8001，LoginReq 单消息）

```
+----------+---------------------------+
| 4 bytes  |  N bytes                  |
| big-endian| Protobuf serialized body |
| body_len |                           |
+----------+---------------------------+
```

- 包头 4 字节大端 uint32 = body 字节数；body 为 Protobuf 序列化字节流。
- 上限：body ≤ 4MB（`Codec.h:11 kMaxBodyLen`）；`body_len == 0` 或超长 → `tryDecodeHeader` 返回 nullopt，调用方关 fd（`main_gateway.cpp:65-66`）。
- 网关包无 type 字节（单消息 LoginReq）。

### 2.2 战斗服 KCP/UDP（8002，多消息复用通道）

```
+----------+---------------------------+
| 1 byte   |  N bytes                  |
| msgType  | Protobuf serialized body  |
+----------+---------------------------+
```

| msgType | 方向 | 消息 | 响应 type |
|---|---|---|---|
| 1 | C→S | CreateRoomReq | 2 |
| 2 | S→C | CreateRoomRsp | — |
| 3 | C→S | JoinRoomReq | 4 |
| 4 | S→C | JoinRoomRsp | — |
| 5 | C→S | FrameInput（无响应，入房间历史） | — |
| 6 | S→C | FrameBroadcast（服务端 100ms tick 主动推） | — |
| 7 | C→S | RejoinRoomReq | 8 |
| 8 | S→C | RejoinRoomRsp | — |

> 注：该 1B type 头与编号表此前只存在于代码/客户端脚本，未写入架构 §5（偏差 D4），本记录固化为契约快照。
