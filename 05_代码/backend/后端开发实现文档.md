# 后端开发实现文档（cpp-game-server-kit）

> 对口岗位：杭州游梦光年 C++ 游戏服务端。纯后端基础设施五件套，无前端、无 HTTP API。
> 本文档对应工作流 step5A，记录模块范围、接口契约、依赖版本、部署启动与自测证据。

## 1. 模块说明

| 模块 | 职责 | 主要落点 |
|---|---|---|
| A 网络库 net | 手写 epoll Reactor：RAII fd、Buffer、Channel variant 分发、EventLoop、TcpServer + 3 worker 线程池 | `include/net/`、`src/net/` |
| B 无锁日志 log | SPSC 环形队列（concepts 约束 + memory_order + 缓存行对齐）+ 后台线程批量刷盘 + 可变参数宏 | `include/log/`、`src/log/` |
| C 登录网关 gateway | Protobuf 编解码（4B 大端包头）+ thread_local MySQL/Redis + sha256(salt+password) 校验 + Redis session | `src/gateway/`、`src/db/`、`include/proto_codec/` |
| D KCP 战斗服 battle | 自研最小 kcp 兼容实现入 third_party + KcpSession/KcpServer + 房间管理 + 100ms 协程帧广播 + 断线重连拉历史 | `src/battle/`、`include/battle/`、`third_party/kcp/` |
| E 压测与检测 | stress_client 长连接压测、bench_queue 队列压测、ASan/Valgrind 脚本、现代 C++ 检查、perf 报告 | `src/tools/`、`scripts/`、`08_测试/perf/` |

复用公共组件：net 库被 echo_server / game_gateway / battle_server 共用；log 队列被 AsyncLogger 与 bench_queue 复用。

## 3. 接口定义

### 3.1 传输与编解码

**登录网关（TCP 8001）**：4 字节大端包头（body 长度）+ Protobuf body。
```
| 4B big-endian body_len | pb body |
```

**战斗服（KCP/UDP 8002）**：1 字节消息类型头 + Protobuf body。
```
| 1B msg_type | pb body |
```

消息类型头映射（战斗服）：

| type | 消息 | 方向 |
|---|---|---|
| 1 | CreateRoomReq | C→S |
| 2 | CreateRoomRsp | S→C |
| 3 | JoinRoomReq | C→S |
| 4 | JoinRoomRsp | S→C |
| 5 | FrameInput | C→S |
| 6 | FrameBroadcast | S→C |
| 7 | RejoinRoomReq | C→S |
| 8 | RejoinRoomRsp | S→C |

### 3.2 消息字段（game.proto）

| 消息 | 字段 |
|---|---|
| LoginReq | username string, password string |
| LoginRsp | code int32, token string, uid int64, msg string |
| CreateRoomReq | token string |
| CreateRoomRsp | code int32, room_id int64 |
| JoinRoomReq | token string, room_id int64 |
| JoinRoomRsp | code int32, members repeated int64 |
| FrameInput | room_id int64, uid int64, input int32 |
| FrameBroadcast | room_id int64, frame_no int32, inputs repeated FrameInput |
| RejoinRoomReq | token string, room_id int64 |
| RejoinRoomRsp | code:int32, frame_no:int32, history:repeated FrameInput |

### 3.3 错误码

| code | 含义 |
|---|---|
| 0 | 成功 |
| 404 | 房间不存在（Join/Rejoin） |
| 其他非 0 | 登录失败（用户不存在/密码错/DB 异常），msg 带原因 |

## 6. 部署与启动

### 6.1 环境前置（每次新 WSL 会话）
```bash
service mysql start
redis-server --port 6380 --bind 127.0.0.1 --daemonize yes   # 避让 6379
```

### 6.2 编译
```bash
bash scripts/build.sh        # cmake -B build + make -j，产物 build/bin/
```

### 6.3 启动服务
| 服务 | 命令 | 端口 |
|---|---|---|
| echo_server | `./build/bin/echo_server 8000` | TCP 8000 |
| game_gateway | `./build/bin/game_gateway 8001` | TCP 8001 |
| battle_server | `./build/bin/battle_server 8002` | UDP 8002 |

### 6.4 配置
`05_代码/backend/.env`（由 `.env.example.template` 复制）：MySQL 127.0.0.1:3306/cpp_game/root 空密码；Redis 127.0.0.1:6380。

### 7.1 已知未达标 / 技术债（详见 `_问题台账.md`）
- **M6**：A/B 比值 1.03（+2.9%），未达 ≥1.30；瓶颈为回环 RTT、同步 read/write 模型、单线程压测客户端，非用户态热点。报告 `08_测试/perf/perf_report.md`。

- 日志模块 AsyncLogger/LOG_INFO 已实现并经队列压测验证，尚未接入网关/战斗服业务链路（D-08/D-09 ⚠️）。

## 8. 不适用项说明

- **前端 / HTTP / OpenAPI**：本项目纯 C++ 后端，无前端页面、无 HTTP 路由，故 `FRONTEND_PORT`、`VITE_API_BASE_URL`、OpenAPI paths 不适用；协议契约以 `proto/game.proto` 为准（step6.5 校验 .proto）。
- **JWT**：不使用 JWT，登录态由 Redis `session:{uid}` token 承载；`.env` 中 JWT_SECRET 为占位、未参与运行。
- **容器化**：docker-compose 模板保留，当前在 WSL 裸机运行，未启用 Docker。
