# 简历项目描述 · cpp-game-server-kit

> 对口：杭州游梦光年 · C++ 游戏服务端开发（作品集）。数字只来自实测产物，出处见文末映射表；未实测/未达标的项在「诚实边界」原样写出。

## A 一句话

C++ 游戏服务端骨架：epoll Reactor 登录网关 + KCP 帧同步战斗服，Protobuf 私有协议，10 条消息、51 条测试用例。

## S 背景

为应聘 C++ 游戏服务端岗，在 WSL2 Ubuntu-22.04、16GB 内存的本机上单人实现一套纯后端服务端骨架，不含前端与战斗数值业务。没有现成框架可用，网络、并发、内存安全都要在本机回环环境自验。

## T 目标

- 打通登录 → 建房 → 进房 → 帧同步广播 → 断线重连主链路，L4 E2E 用例通过。
- 长连接、无锁队列、内存安全、登录延迟、现代 C++ 特性逐项压测验证。
- 调优收益、代码规模两项未达基线，如实记为技术债，不美化。

## A 动作

1. 基于 epoll LT 手写 one-loop-per-thread Reactor（EventLoop/TcpServer/Channel/Buffer），worker 线程 round-robin，同一份 net 库复用给 echo、gateway、battle 三个进程。
2. 用 std::atomic + memory_order 手写 SPSC 无锁环形日志队列，alignas(64) 缓存行对齐防伪共享，后台 AsyncLogger 批量刷盘。
3. 网关走 TCP + Protobuf 编解码：MySQL 预编译查用户、Redis 写 session；战斗服走 UDP + 自研最小兼容 KCP 收发，房间管理与定时广播协程。
4. 搭四层 pytest 框架（L1 单元 / L2 接口 / L3 中间件 / L4 E2E）加 7 条 P0 回归；ASan、Valgrind 跑 gateway/battle 全路径。
5. 修复独立 Review 发现的会话表竞态、超时 UAF、战斗服鉴权缺失、KCP 未上业务路径四个 P1 隐患并回归通过。

## R 结果（均为实测）

- 用例 51 条：49 passed / 2 xfailed / 0 failed；P0 7/7。
- 长连：1000 连接 300.01s 断开 0，服务端 RSS 增量 236KB。
- 无锁队列：百万条 push/pop 零丢失，1220 万条/s（纯内存对账，未含后台写盘计时）。
- 内存安全：ASan 零 error；Valgrind definitely lost=0、ERROR SUMMARY 0。
- 登录：单请求 RT 2.4–2.9ms；10/20/50 并发 701.9 / 533.4 / 536.0 TPS，错误率 0。
- 房间：49/49 进房，断线重连 1.3ms，服务端 CPU 快照 0.3%（4 线程）。
- 未达成：调优 A/B 比值 1.046（基线 ≥1.30）；自研 1935 行（基线 3000 起）。
- 未验证：广播应用层 P99 延迟。

## C 关键词（三档，对齐 00_JD对账表）

- **用过**：C++17/20（RAII、std::move、variant/optional、concepts、stackless 协程）、epoll、TCP/UDP/KCP、多线程/线程池/协程、无锁队列与内存模型、Protobuf、MySQL 索引与预编译、Redis session、ASan/Valgrind、pytest 四层框架。
- **了解 / 部分落地**：STL 性能优化（vector 预分配、optional 抽象在位，调优收益未达标）；缓存策略（session 落地，房间态未落 Redis）；Linux 故障排查（线程级 ps/top -H 采样，perf 不可用）。
- **未用**：MySQL/Redis 连接池、Docker、gRPC/HTTP/WebSocket/SSL、跨服分布式、Testcontainers、bcrypt/argon2 慢哈希、匹配与战斗数值业务。

## D 可演示点（验收清单真实通过条目）

1. L4 E2E 主链路：登录 → 建房 → 双人进房 → 发帧 → 收 KCP 广播段 → 断线重连恢复（清单 A6）。
2. 反向用例：伪造 token、A 的 token 配 B 的 uid、8 条 SQL 注入载荷均被拒绝（清单 C4/C5/C6）。
3. P0 回归 `p0_runner.py` 7/7 通过，脚本可在新会话自包含拉起服务后复跑。

## E 诚实边界

- 房间/成员/帧历史当前是内存态，未落 Redis，服务重启即丢（Q-013）。
- KCP 为自研最小兼容实现，ARQ 重传/滑动窗口未做丢包注入端到端验证。
- 登录 20 并发后 TPS 见顶约 530；DB/Redis 访问仍是回调内同步阻塞，未异步化、无连接池。
- 安全侧 deferred：FrameInput 入口未鉴权与归属校验、密码单轮 SHA-256、连接参数硬编码源码、Redis 无密码、服务监听 0.0.0.0、成员表不去重。
- WSL 内核与 perf 版本不匹配，无火焰图；压测为 Python 多线程与自研 C++ 客户端，未用 JMeter；L3 中间件用例直连本机 MySQL/Redis，未用 Testcontainers 隔离。
- 不含战斗数值、技能、匹配、支付、前端与跨服；以上均为设计阶段主动排除的范围。
