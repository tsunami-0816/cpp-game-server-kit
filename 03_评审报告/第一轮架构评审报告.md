## 三、问题清单

### P0 致命问题（会导致链路不通/指标必挂/选型硬冲突）

**无 P0。**

核心四条链路（L1 登录/L2 帧同步/L3 断线重连/L4 Echo 压测）在架构上都有完整数据流和组件支撑，技术选型在 WSL2 Ubuntu 22.04 上 apt 可装，无版本硬冲突。

### P1 重要问题（不阻塞但必须在 step2 第二轮补设计，否则 step5 会卡壳）

**P1-01：M7 的 std::variant/optional/concepts 没有明确落地类**
- 问题描述：架构文档 §1 和 §9 提到要用 std::variant/optional/concepts，但 30 个 D 项里没有一个具体类声明"我在这里用 variant/optional/concepts"。照现在的设计写代码，这三类特性大概率 grep 不到。
- 影响范围：M7 验收时 grep 不到，现代 C++ 亮点少三个
- 修改建议：在架构文档里补明确落地点：
  1. `Buffer::TryReadMessage()` 返回 `std::optional<size_t>`（不够包头长度就返回 nullopt）
  2. 事件回调上下文用 `std::variant<ClientContext, TimerContext, KcpContext>` 替代 std::any（类型安全）
  3. `LockfreeQueue<T>` 模板加 `concepts` 约束：`template<typename T> requires std::is_trivially_copyable_v<T> class LockfreeQueue`
- 落点：D-02 Buffer、D-04 EventLoop、D-07 LockfreeQueue 三处补一句

**P1-02：MySQL 多线程连接池缺失**
- 问题描述：架构 §3.1 说"预建 4 个 MySQL 连接"，但 D 清单里只有 D-12 MysqlConn（单连接 RAII），没有连接池类。game_gateway 有 N 个 worker 线程，每个线程都会查 MySQL，libmysqlclient 的连接不是线程安全的，两个 worker 同时用一个 MYSQL* 会崩。
- 影响范围：M4 登录链路在并发登录时会段错误
- 修改建议：补一个 D 项 `MysqlConnPool`：启动时预建 N 个连接（N=worker 数），每个 worker thread_local 持有自己的连接，不需要锁。架构 §3.1 线程模型里补一句"每个 worker 线程持有自己的 MySQL 连接，thread_local，无线程安全问题"。

**P1-03：Redis hiredis 同步连接的线程安全未说明**
- 问题描述：hiredis 的 redisContext 不是线程安全的，gateway 的 N 个 worker 线程都要写 Redis session，战斗服的 N 个 worker 都要读写 room key。架构里没说怎么处理。
- 影响范围：并发操作 Redis 会 core dump
- 修改建议：和 P1-02 一致——每个 worker 线程 thread_local 持有自己的 hiredis 连接，启动时按 worker 数建 N 个连接。Redis 单实例 qps 上限 10w+，本项目压测量级（几百 QPS）连多少个都够。

### P2 建议优化（不阻塞，step5 开发时顺手做）

**P2-01：日志文件轮转没设计**
- 问题：AsyncLogger 一直写一个 log 文件会无限大。MVP 阶段可以不做自动轮转，但要在 README 里写"测试时手动 truncate"。
- 建议：step5 开发时加个简单开关——文件大小超过 100MB 就 rename 成 xxx.log.1 重新开新文件。10 行代码的事。

**P2-02：KCP conv_id 分配时机没说**
- 问题：客户端第一次 KCP 连上来，conv_id 是客户端自己指定还是服务器分配？libkcp 要求收发双方 conv_id 一致。
- 建议：MVP 简化——客户端 KCP 连上来时先用一个固定 conv_id（比如 0x11223344）发 JoinRoom 包，服务器校验 token 后在回包里告诉客户端新的 conv_id，客户端切换。这是 1 个包的事，不用搞复杂握手。

**P2-03：Protobuf 解析失败/包体超长的错误码没列**
- 问题：§5.3 错误码表只有业务错误，没有"Protobuf 反序列化失败""包体超过 4MB 上限"这种协议层错误。
- 建议：补 4001=协议解析失败、4002=包体超长（>4MB 直接断 fd）。
