## 四、移交 step11 的脚本/模板缺陷

1. **forbid 词表粗粒度误伤如实技术债**：5.5 / 7.5 / 基线表的 forbid 应参照 8.5 安全报告口径，细化为「只禁结论性否定（Review 未通过 / 主流程未通 / P0 未清零）」，不误伤「未达标（技术债 deferred）」「未重置自增（已修复）」「无 TODO 占位」这类如实归属与根因描述。
2. **纯后端项目缺不适用豁免通道**：前端 UI 报告、taste 报告、openapi.json 三条目未配 optional / 项目类型跳过条件；纯后端新项目（创建晚于 launch_date）会被机械判 MISSING。建议 steps.yaml 按看板「项目类型 / 是否有前端」配跳过规则，或门禁识别「不适用登记占位」。
3. **optional mode 子串匹配过宽**：5B 精修记录的 mode 匹配用子串 `精修 in board_mode`，看板说明文字含「无 UI 精修需求」即被误判精修模式；建议改为精确匹配设计模式取值。
4. **prepush 真实 .env 豁免名单不全**：`check_tracked_files` 豁免集合仅含 `.env.example/.sample/.template`，本项目模板名 `.env.example.template` 被误判为真实 `.env`（内容已核实全空占位）。已在本地 `prepush_check.py` 豁免集合补入该后缀；建议规则按「`.env.example*` / `.env.*.template` 模板后缀」统一识别，而非枚举文件名。
5. **prepush Password Assignment 规则误伤非密钥取值**：正则把 proto 字段类型标注（口令/令牌字段后的 string 类型名）、登录后局部令牌变量名（old/new 等局部变量）、语义占位串（`dev-local-no-jwt-not-used`）判为疑似密钥。已通过 `.secretignore` 豁免测试夹具/种子 sql，文档样例改写为非赋值叙述形态；建议规则增加类型名/大写常量/局部变量白名单，并扩充占位词表（`dev-local`、`not-used`、`fake-*` 等）。
6. **`.gitignore` 运行数据目录通配误伤测试夹具**：`data/` 规则忽略任意层级同名目录，把 `qa-automation/data/test_accounts.yaml`（用例引用的边界/反向夹具）一并排除，CI clone 后 collect 缺文件。建议模板把运行时数据目录写成显式相对路径（如 `runtime/data/`），或为测试夹具目录预留 `!**/qa-automation/data/` 例外段。
