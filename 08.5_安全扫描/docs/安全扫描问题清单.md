# 安全扫描问题清单（step 8.5）

> 分级口径：P0 可直接导致沦陷/拖库/RCE/硬编码真实密钥/SQL 注入/未鉴权管理员接口；P1 可导致越权/敏感泄露/可利用高危依赖；P2 配置不当、弱加固、利用门槛高；P3 加固建议。
> 本轮结论：**P0 = 0，P1 = 0**；P2/P3 全部 deferred 留档，不阻塞 step9 验收（内网 demo 边界，去向见「归属」列）。
> 扫描时间：2026-11-11；环境：WSL2 Ubuntu-22.04，gateway 0.0.0.0:8001 / battle 0.0.0.0:8002 / MySQL 127.0.0.1:3306 / Redis 127.0.0.1:6380。

## 三、P3 加固建议（deferred）

| ID | 现象 | 证据 | 修复建议 |
|---|---|---|---|
| Q-027 | 登录失败回包可区分用户存在性：1001 `user not found` vs 1002 `wrong password`，存在用户名枚举面 | `penetration_probe.log` P-1/P-2 | 对外统一模糊错误码（如「用户名或密码错误」），细节仅记服务端日志 |
| Q-028 | 登录无失败次数限流、无账号锁定/验证码，存在暴力破解面 | `main_gateway.cpp:56-105` 无计数分支 | 按 uid+IP 加失败计数与临时锁定；限流中间件 |
| Q-029 | Redis 命令用 `%s` 字符串插值（`setEx/get/del`）；当前 key=`session:<uint64>`、val=hex token，不可控，无注入面 | `RedisConn.cpp:20-42` | 改用 `redisCommandArgv` 二进制安全接口，避免特殊字符破坏 RESP |
| Q-030 | UDP 会话按 (ip,port) 建 KcpSession，无会话数上限、无 KCP conv 校验；伪造源地址可膨胀内存 | `KcpServer.cpp:41-71` | 加上限与 LRU 淘汰；校验 conv 一致性 |
| Q-031 | `genToken()` 未检查 `open`/`read` 返回值，fd 未判负，读取不足 32 字节时补零 | `main_gateway.cpp:34-46` | 判 fd>=0、循环 read 满 32 字节，失败返回错误 |
| Q-032 | `probe_state.py:20` `subprocess.run(..., shell=True)`；命令为固定字符串（ss/mysql/redis-cli），无用户可控拼接，无注入面 | `probe_state.py:19-21,39-44` | 改为列表参数形式，去掉 shell=True |
| Q-033 | `Buffer::take(n)` 未校验 `n <= readable()`，越界迭代器区间为未定义行为；该工具类当前未被业务路径调用（不可达） | `include/net/Buffer.h:25-29` | 补 `if (n > buf_.size()) n = buf_.size()` 或断言 |
