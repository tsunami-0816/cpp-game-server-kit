# 自由探索上手指南 · 给第一次上手的人

> 这份指南不讲代码原理，只讲：**点哪里、敲什么、看到什么算对、想自己改着试怎么改**。
> 配套演示脚本：`scripts/explore_demo.py`（大白话分步演示）；一键入口：项目根目录 `一键探索演示.bat`。

## 0. 先搞懂：这套东西是什么

- 这是一个**纯后台游戏服务器程序**，**没有网页、没有按钮界面**。你看不到一个可点击的游戏画面。
- 它由两个服务组成：
  - **网关（gateway）**：TCP 端口 **8001**，管登录、发 token 门禁牌。
  - **战斗服（battle）**：UDP 端口 **8002**，管建房、进房、发帧、广播、重连。
- 所谓"操作"，就是**用一个小客户端脚本把消息发给服务器，再读它回了什么**。演示脚本已经把发包/收包写好了，你只需要运行它、看输出。
- 种子账号（数据库里就这两个）：

  | 用户名 | 密码 | 编号 uid |
  |---|---|---|
  | user1 | 123456 | 1 |
  | user2 | 123456 | 2 |

## 1. 最快方式：双击一键演示（推荐先做这个）

1. 打开本项目根目录（克隆到本地后的仓库文件夹）。
2. 找到 **`一键探索演示.bat`**，**双击**它。
3. 会弹出一个黑色命令行窗口，自动拉起服务并跑演示，大约 10 秒。
4. 窗口里会按 7 步打印：登录 user1 → 登录 user2 → 建房 → 进房 → 发帧收广播 → 断线重连 → 4 个反向用例。每步都有"动作 / 回包 / 人话"三行。
5. 看完按任意键关闭窗口。

> 脚本会先把 MySQL / Redis / 两个服务拉起来；演示结束后服务仍在后台跑着，方便你接着自己试。

## 2. 看懂回包：字段和错误码人话表

### 2.1 回包字段

| 字段 | 人话 |
|---|---|
| `code` | 结果码。**0 = 成功**；非 0 = 被拒绝，对照下面错误码表 |
| `uid` | 账号编号，user1=1，user2=2 |
| `token` | 登录成功后拿到的"门禁牌"，64 位字符串；后面建房/进房/重连都要带上，过期或被冒充会被拒 |
| `room_id` | 房间号，从 1000 开始递增 |
| `members` | 房间里当前所有人的 uid 列表 |
| `frame_no` | 当前帧号；`history` 是掉线期间攒下、还没广播给你的积压帧 |
| `input` | 这一帧你按了什么（示例用一个数字代替按键） |

### 2.2 错误码对照表

| code | 含义 | 什么时候出现 |
|---|---|---|
| 0 | 成功 | 一切正常 |
| 1001 | 用户不存在 | 填了数据库里没有的账号 |
| 1002 | 密码错误 | 账号对、密码错 |
| 1003 | token 无效/过期/被冒充 | 没带 token、带了假 token、或用旧 token |
| 2001 | 房间不存在 | 进房/重连填了一个没开过的房号 |
| 2002 | 房间已满员 | 房间人数到 50 上限（本轮演示不触发） |

## 3. 自己动手试（自由探索的核心玩法）

演示脚本文件：`scripts/explore_demo.py`，用记事本或 Trae/Cursor 打开。**只改下面列出的几处**，保存后重新双击 bat，看回包怎么变。

| # | 想试什么 | 改哪里（文件内位置） | 改成什么 | 预期看到 |
|---|---|---|---|---|
| T1 | 密码再试错一次 | 第 7.1 步 `login("user1", "wrongpass")` | 密码换成 `abc123` | 仍是 `1002 密码错误` |
| T2 | 换个不存在的账号 | 第 7.2 步 `login("nobody_xyz", "123456")` | 账号换成 `hello`、`admin` 等 | 仍是 `1001 用户不存在` |
| T3 | 用 user2 的身份去冒充 | 第 1 步登录后，把第 3 步建房请求里的 `uid` 改成 2，token 仍是 user1 的 | token 与 uid 对不上 | `1003 token 无效`（水平越权被拦） |
| T4 | 进一个瞎填的房号 | 第 4 步 `j.room_id = 999999` | 改成 123456 | `2001 房间不存在` |
| T5 | 改一帧操作数字 | 第 5 步 `fi1.input = 42` / `fi2.input = 7` | 改成 1、99 等任意整数 | 广播段仍能收到；积压帧里的数字随你填的变 |
| T6 | 重复登录看旧牌失效 | 自己在脚本末尾再调一次 `login("user1","123456")`，拿第二次的 token 建房 | 对比第一次 token | 第二次登录后，第一次的旧 token 再用会 `1003` |

> 改坏了没关系：把改动还原，或对照本文件内容改回即可。脚本不写坏数据库，账号种子在 MySQL 里不会被改。

## 4. 命令行方式（备用，不想双击 bat 时用）

1. 按 `Win + R`，输入 `wsl` 回车，打开 Ubuntu 终端。
2. 粘贴下面这行回车（自动起服务 + 跑演示）：

   ```bash
   # 在本项目根目录（WSL 内）执行
   bash scripts/explore_demo.sh
   ```

3. 只跑自动化全量回归（49 条用例）：

   ```bash
   cd 08_测试/qa-automation
   bash services.sh start
   bash run_pytest.sh -q
   ```

## 5. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 窗口里报 `Connection refused` / 8001、8002 连不上 | 服务没起来。重新双击一次 bat；它会先自动拉起服务。WSL 每次新会话不会保留上次的后台服务 |
| 中文输出乱码 | 确认窗口是 `chcp 65001`（bat 已自动设置）；命令行方式若乱码，先跑 `export LANG=C.UTF-8` |
| 提示 `wsl: command not found` | 本机 WSL 未安装或发行版未注册，先在 PowerShell 跑 `wsl --install`（本项目环境已具备，一般不会遇到） |
| 想清空现场重来 | 清 Redis `session:*`/`room:*` 键后 `bash 08_测试/qa-automation/services.sh restart`；种子账号在 MySQL `users` 表，重置方式见 `07_联调/数据重置记录.md` |

## 6. 探索完怎么回填验收

- 把你在 T1–T6 或自由尝试中发现的**不对、奇怪、做不到**的地方，记到 `09_验收/最终验收清单与报告.md` 第一步的「自由探索记录区」。
- 然后对照报告第二节清单逐条看：每条都有"操作 / 输入 / 预期 / Agent 预走结果"，你在「用户回填」列填 **通过 / 不通过 / 备注**。
- 拿不准算不算问题，先记下来交给 Agent 分级，不要自己判断要不要修。
