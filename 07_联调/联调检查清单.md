## 1. 核心链路走查（L1–L6）

### L1 · 登录全链路（TCP 8001）

| 步骤 | 输入 | 预期结果 | 一致性检查点 |
|---|---|---|---|
| L1.1 | TCP 连 8001，发 `LoginReq(user1/123456)`（4B 大端长度头 + pb body） | `LoginRsp code=0`，`uid=1`，`token` 64 位 alnum，`msg=ok` | — |
| L1.2 | 同上 `user2/123456` | `code=0`，`uid=2`，token 64 位 | — |
| L1.3 | Redis 核对 `session:1`、`session:2` | key 存在，值 == 回包 token；`TTL` ≈ 7200（秒，允许 719x~7200） | session 与 token 逐字符一致；TTL 非 -1（不永久存，基线 §4.5） |
| L1.4 | 登录耗时观测（M4 口径） | 本机端到端响应 < 50ms（WSL2 回环，参考值，step8 正式测） | 记录单次耗时，不做压测 |

### L2 · 创建房间（KCP/UDP 8002，type=1→2）

| 步骤 | 输入 | 预期结果 | 一致性检查点 |
|---|---|---|---|
| L2.1 | user1 持 token1 发 `CreateRoomReq(token,uid=1)` | `CreateRoomRsp code=0`，`room_id ≥ 1000` | 非法 token 不进建房分支（见 L6.1） |
| L2.2 | user1 再建第二个房（独立 socket） | `room_id` 自增，比 L2.1 大 1 | 房间号单调递增（`g_nextRoomId` 原子自增） |

### L3 · 双人进房（type=3→4）

| 步骤 | 输入 | 预期结果 | 一致性检查点 |
|---|---|---|---|
| L3.1 | user2 持 token2 发 `JoinRoomReq(token2, room_id=L2.1, uid=2)` | `JoinRoomRsp code=0`，`members` 集合 == {1, 2} | members 含双方 uid；顺序不作硬断言（vector 追加序） |
| L3.2 | 复核房间归属 | user1 为房主（建房时入 members），user2 追加在后 | 与 L2.1 房间号一致，未串房 |

### L4 · 帧输入 → 100ms 帧广播（type=5 → type=6）

| 步骤 | 输入 | 预期结果 | 一致性检查点 |
|---|---|---|---|
| L4.1 | user1 发 `FrameInput(room_id, uid=1, input=42)`；user2 发 `FrameInput(room_id, uid=2, input=7)` | 服务端入房间历史（最近 100 条截断）；本消息无响应包 | 服务端无报错；历史入队（经 L5 重连回包 history 侧面核对未广播积压） |
| L4.2 | 等待 ≥1 个 tick（≥100ms），两成员 socket 收广播 | 成员 socket 收到 UDP 广播段（type=6 经 KCP `ikcp_send` 封装） | 裸 Python 客户端只见 KCP 段字节流，**不强解 FrameBroadcast pb**（既定取舍，见 §4 未覆盖场景）；段长 > 0 |
| L4.3 | frame_no 递增观测 | 服务端 `frameNo` 每轮广播 +1；可由后续重连回包 `frame_no` 侧面核对 | 重连回包 frame_no 非回退（单调不减） |

### L5 · 断线重连恢复（type=7→8）

| 步骤 | 输入 | 预期结果 | 一致性检查点 |
|---|---|---|---|
| L5.1 | 制造断线：关闭 user1 的 UDP socket，重新建 socket 发 `RejoinRoomReq(token1, room_id, uid=1)` | `RejoinRoomRsp code=0`，`frame_no` 与房间当前 frameNo 一致，`history` 为未广播积压帧 | frame_no 连续/不回退；history 条数 == 入队后尚未被 tick 广播清出的帧数 |
| L5.2 | 积压帧核对（tick 前快速路径） | 在 <100ms 内连发若干 FrameInput 后立即重连，`history` 应 ≥1（尚未广播） | history 内 FrameInput 的 uid/input 与上报一致（本路径回包为 sendRaw 裸 pb，可解） |
| L5.3 | 重连后成员恢复 | 重连会话重新进入房间 members；后续广播段仍可达该 socket | 重连后再收一轮广播段 |

### L6 · 异常分支与错误码（对照契约 §4）

| 步骤 | 输入 | 预期 code | 契约语义 | 一致性检查点 |
|---|---|---|---|---|
| L6.1 | 伪造 token 建房 / 进房 / 重连 | `1003` | token 无效 | 三个 battle 入口均拒；空 token 同 1003 |
| L6.2 | 登录不存在用户 `nobody_xyz` | `1001` | 用户不存在 | 回包 token 为空 |
| L6.3 | 登录 user1 错密码 `wrongpass` | `1002` | 密码错误 | 回包 token 为空 |
| L6.4 | 加入不存在房间 `room_id=999999` | `2001` | 房间不存在 | 重连不存在房间同为 2001 |
| L6.5 | 房间满员 `2002` | 分支存在（代码 `members.size() >= 阈值`） | 房间已满 | ⚠️ 阈值实现为 8，基线 M5 契约为 50，偏差记 **Q-014（open P2，本步不动，step8 压测前对齐）**；本步只做代码走查确认 2002 分支存在，不实测 8 人触发 |

## 3. 问题分级口径（与执行约定一致）

- **P0 阻塞**：核心链路完全中断、主流程走不通。
- **P1 严重**：核心链路部分异常、关键数据不一致、无异常兜底。
- **P2 一般**：非核心链路异常、联调瑕疵（本步不主修，记 deferred 写清去向）。
- **P3**：文案/提示类小问题。
- 「可运行但不够优」「可扩展但不够好」一律 P1/P2，不包装成 P0。

## 4. 未覆盖场景与既定边界（本步不扩大范围）

1. **KCP 可靠传输/重传/滑动窗口端到端验证**：裸 Python 客户端不模拟 KCP 接收窗口与 ACK，仅见到 KCP 段；pb 级 FrameBroadcast 内容一致性待 step8 补 KCP 客户端或服务端观测日志后核对。（沿用 step6 §6、Q-007 修复后口径）
2. **2002 满员实测**：受 Q-014 阈值偏差限制，本步不构造 8 人/50 人满员场景；满员压测归属 step8 M5。
3. **3001 内部错误 / 4001 解析失败回包 / 4002 超长回包**：解码层已有断连防护，响应包未出，沿用 Q-009 / D3 deferred，归属 step8 健壮性补齐。
4. **房间/成员/帧历史 Redis 持久化**：当前内存态，重启丢失，Q-013 deferred。
5. **50 人房间压测、广播 P99 延迟、CPU 占用**：属 step8 M5 全量测试，本步只做 2 人串联走查。
6. **AsyncLogger 接入业务链路**：Q-004 deferred，业务日志仍走 std::cerr/std::cout。
