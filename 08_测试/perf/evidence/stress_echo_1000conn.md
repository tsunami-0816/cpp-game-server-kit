# M1 长连接压测记录（echo_server + stress_client）

## 环境
- WSL Ubuntu-22.04，g++ 11.4.0，Release -O2
- echo_server 监听 8000，3 worker 线程；stress_client 单线程 epoll 管理全部连接
- 客户端/服务端同机 127.0.0.1，`ulimit -n 65535`

## 1000 连接 × 10 秒（初步验证）

| 指标 | 实测值 | M1 判据 | 结论 |
|---|---|---|---|
| 成功连接 | 1000 / 1000 | ≥1000 | ✅ |
| 中途断开 | 0 | 断开数 = 0 | ✅ |
| 当前在线 | 1000 | — | ✅ |
| 发包总数 | 768000 | — | — |
| 收包总数 | 767940 | — | 收尾在途 60 条，正常 |
| 耗时 | 10.00 s | — | — |
| QPS | 76758 回显/s | — | — |
| 平均延迟 | 12.43 ms | — | 偏高，见技术债 |
| 最大延迟 | 17.50 ms | — | — |
| 客户端 RSS | 3.66 MB | RSS 波动 < 50MB | ✅ |

## 50 连接 × 3 秒（对照）
- 成功 50，断开 0，QPS 122358，平均延迟 0.40 ms，最大 2.53 ms，RSS 3.59 MB

## 已知技术债（待 M6 调优 / 后续迭代）
- 服务端连接回调仍为读事件里同步 read/write，worker EventLoop 未做真正的异步读写流水线；1000 连接下平均延迟 12.4ms 高于 50 连接的 0.4ms，瓶颈在服务端收发路径而非客户端。
- 5 分钟长稳压测（M1 完整判据）在 step8 全量测试阶段复跑并补曲线。

## 复现命令
```bash
# 服务端
ulimit -n 65535 && ./build/bin/echo_server 8000
# 客户端
ulimit -n 65535 && ./build/bin/stress_client -c 1000 -d 300 -p 8000
```
